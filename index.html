How the SDK works

Five stages, every time a model runs

The first three stages happen once, when the model is loaded. The last two repeat with every reply, so the setup keeps improving.

STAGE 1

Inspect

Reads the model file and measures the device before anything is loaded.

Model layers, size per layer, memory per word of conversation · CPU cores, free RAM, GPU memory
STAGE 2

Plan safely

Lists every possible way to run the model and removes those that would not fit or would hurt quality.

Precision versions × CPU/GPU split × threads × batch, checked against free memory minus a safety reserve
STAGE 3

Start fast

Predicts the fastest safe setup, or quickly measures each version, and starts there.

Short speed test per precision (about 5 s); compressed versions can be created automatically
STAGE 4

Run & protect

Answers requests while watching memory, temperature and speed; recovers instantly from failures.

Live telemetry, switching before memory runs out, rollback to the last working setup
STAGE 5

Learn & improve

Scores each reply and learns which setup works best on this device; prepares the next change in the background.

Reinforcement learning (Q-learning); knowledge saved per model and per device
↻ Stages 4 and 5 repeat after every reply. Only how the model runs changes; the model's knowledge is never modified.

What the SDK does

Everything it takes care of, automatically

Bring in any model

  • Model library names, downloaded on request
  • HuggingFace models by name or link
  • Local model files, validated before use
  • Any architecture: Llama, Qwen, Gemma, Mistral, Phi…
  • "Did you mean…" suggestions for typos

Understand device & model

  • Reads the model structure without loading it
  • Detects CPU cores, RAM, NVIDIA GPU
  • Calculates memory for every possible setup
  • Calibrates its estimates to the real device
  • Health check that explains how to fix issues

Make it fast

  • Creates compressed versions (high quality / fastest)
  • Speed-tests each version on load
  • CPU/GPU split chosen for the device
  • Threads and batch matched to the processor
  • Conversation memory that grows on demand

Keep quality in check

  • Measures answer quality of every version
  • Quality limit you can set
  • Excludes versions that fall below it
  • Never alters the model's knowledge

Protect the device

  • Refuses setups that would not fit
  • Keeps a memory reserve for other programs
  • Switches down when memory gets tight
  • Automatic rollback on failures
  • Remembers and avoids failing setups

Learn & explain

  • Learns from every reply (reinforcement learning)
  • Prepares changes in the background
  • Remembers the best setup per device
  • Live insight: speed, memory, decisions
  • Plain-language summary of what it chose and why
Source code at a glance

A few lines to use it, a clear engine underneath

Short excerpts from the open repository. The full source, tests and examples are on github.com/sripad2020/EdgeMind.

examples/01_quickstart.py
import air_sdk

# Any model: an Ollama name, an hf.co/... link, or a local .gguf file
with air_sdk.load("qwen2.5:0.5b") as llm:
    print(llm.ask("What is the capital of France?"))

    for piece in llm.stream("Write a two-line poem."):
        print(piece, end="")

    chat = llm.conversation(system="Be brief.")
    chat.say("My name is Asha.")
    print(chat.say("What is my name?"))   # remembers: "Asha"

    print(llm.summary())   # what it chose for this device, and why

One call does the setup

load() inspects the model and the device, filters unsafe setups, runs a quick speed test and starts on the best one. Everything after that is ordinary asking and chatting.

Options: device, goal (balanced / speed / latency / memory), quality limit, max context, download if missing.

air_sdk/engines/space.py
def check(self, pos, budget, blacklist) -> Rejection | None:
    """Deterministic safety rules. Returns None if safe. O(1)."""
    if not self.in_range(pos):
        return Rejection.OUT_OF_RANGE
    if not self.precision.is_quality_ok(pos.variant, pos.kv):
        return Rejection.QUALITY
    est = self.estimate(pos)
    if est.ram_bytes > budget.ram_bytes:
        return Rejection.RAM
    if est.vram_bytes > budget.vram_bytes:
        return Rejection.VRAM
    if self.config_at(pos).key in blacklist:
        return Rejection.BLACKLISTED
    return None

The red cubes in the 3D view

Before any setup is used, it must pass these fixed rules: quality limit, free RAM, free GPU memory, and "has not failed before". The learning agent can only choose among setups that pass.

Budget = free memory now + memory the current model would release − a safety reserve.

air_sdk/rl/qtable.py
def update(self, state, action, reward, next_state, next_mask, *,
           alpha, gamma, prior=0.0, next_priors=None):
    """Q(s,a) <- Q(s,a) + alpha * (r + gamma * max Q(s',a') - Q(s,a))"""
    old = self.q(state, action, prior)
    target = reward + gamma * self.max_q(next_state, next_mask, next_priors)
    td_error = target - old
    new = old + alpha * td_error
    self.set(state, action, new, self.visits(state, action) + 1)
    return new, td_error

How it learns

Tabular Q-learning: after each reply, the value of "this action in this situation" moves toward the reward it actually produced plus the best value reachable next. No neural networks, so every number can be inspected.

Saved per model and per device, so learning survives restarts.

air_sdk/rl/reward.py
t   = clamp(m.tokens_per_second / baseline.tokens_per_second, 0, 4)
lat = clamp(baseline.ttft_s / m.ttft_s, 0, 4)
mem = clamp(1 - m.peak_memory_bytes / m.memory_budget_bytes, -1, 1)
q   = clamp(m.quality_loss / max_quality_loss, 0, 1)
switching = weights.switching * switching_share(m.switch_s, m.request_s)

total = (weights.throughput * (t - 1) + weights.latency * (lat - 1)
         + weights.memory * mem - weights.quality * q - switching)

What "better" means

Each reply is scored on speed, time to first word, memory left free and measured quality loss, minus any time the user waited for a reload. The weights change with the goal you pick.

Failures (e.g. out of memory) receive a fixed penalty and are avoided afterwards.

air_sdk/quantize.py
def quantize_q8_0(rows):
    """Q8_0: per 32 values, d = max|x| / 127 (fp16), qs = roundf(x / d) (int8)."""
    blocks = rows.reshape(-1, QK)
    amax = np.abs(blocks).max(axis=1)
    d = amax / np.float32(127.0)
    inv = np.divide(1.0, d, out=np.zeros_like(d), where=d != 0)
    out = np.empty(blocks.shape[0], dtype=_Q8_DTYPE)
    out["d"] = d.astype(np.float16)
    out["qs"] = _roundf(blocks * inv[:, None]).astype(np.int8)
    return out.tobytes()

Compression on the device

Turns a full-precision model into an 8-bit (or 4-bit) version, block by block, in the exact format llama.cpp uses. Tests check the output byte for byte against llama.cpp's reference method.

0.68 GB → 0.36 GB (8-bit) → 0.21 GB (4-bit) in about 13 s.
